# Спецификация: Rich Text Formatting для дайджеста

## Цель

Перевести единый дайджест Бердянска с визуальной имитации Markdown на нативную разметку Telegram Rich Messages:

- заголовок дайджеста — нативный `heading`;
- название каждой группы — отдельный нативный `heading` меньшего размера;
- новости внутри группы — нативный маркированный список;
- ссылка на исходное сообщение — компактная кликабельная `↗` в конце пункта;
- один дайджест остаётся одним сообщением, если Telegram позволяет его размер.

## Согласованный вид

```text
Дайджест Бердянска · 07 августа 2026

📌 Предупреждения
• Напряжение нестабильно… ↗
• В некоторых районах нет воды… ↗

📌 Другое
• … ↗
```

В Telegram первая строка и названия групп должны быть настоящими заголовками, а пункты — элементами `<ul>`, а не символами `•` в обычном тексте.

## Архитектурное решение

Текущая версия `python-telegram-bot` (22.6) не содержит метода `sendRichMessage`, поэтому добавляется небольшой прямой HTTP-адаптер к официальному Bot API. Это позволит использовать Rich Messages без замены всей Telegram-библиотеки.

Форматтер будет формировать структурированный документ Rich Messages, а отправитель — сериализовать его в JSON и вызвать `sendRichMessage`. Для ссылки используется RichTextUrl с текстом `↗` и URL исходного сообщения.

Существующий Markdown-путь сохраняется как fallback: если Telegram отклонит Rich Message или API окажется недоступен, дайджест отправляется обычным Markdown-сообщением. Это не должно создавать второе сообщение при успешной отправке Rich Message.

## Ограничения и совместимость

- сохраняются текущая очистка дублирующихся bullet-меток, скрепок и стрелок;
- сохраняется удаление футера, статистики и карточки источника;
- сохраняются ссылки на конкретные сообщения каналов;
- очистка старых дайджестов продолжает работать по `message_id`, возвращённому Bot API;
- при превышении лимита сообщение разбивается по группам/пунктам, не разрывая JSON-блок и не оставляя пустой заголовок;
- старый Markdown-форматтер остаётся доступным для обычных команд и аварийного fallback;
- тесты проверяют JSON-блоки, типы заголовков, маркированный список, ссылку `↗`, разбиение и fallback.

## Что не входит в эту задачу

- нумерованные списки;
- таблицы, цитаты, медиа и интерактивные элементы;
- Rich Message Draft для потоковой генерации;
- изменение промпта модели или групп дайджеста.

## Источник API

Используется официальный метод Telegram Bot API `sendRichMessage` и типы `InputRichBlockSectionHeading`, `InputRichBlockList`, `InputRichBlockListItem`, `RichTextUrl`.
