# Бердянск: выбор форумных тем из источника

## Цель

Читать из группы `@Berdyansk_drb` только две форумные темы:

- `235525` — «Проблемы ЖКХ»;
- `43339` — «Новости Бердянска».

Все остальные темы группы не должны попадать ни в сбор сообщений, ни в промежуточные сводки, ни в финальный дайджест.

## Решение

Расширить конфигурацию источника необязательным списком `topics`. Один источник Telegram может содержать несколько выбранных форумных тем:

```yaml
- id: "@Berdyansk_drb"
  name: "Бердянск Свежие Объявления"
  topics:
    - id: 235525
      name: "Проблемы ЖКХ"
    - id: 43339
      name: "Новости Бердянска"
```

Источники без `topics` сохраняют текущее поведение и читаются целиком.

## Поток данных

1. Сборщик один раз разрешает Telegram-сущность `@Berdyansk_drb`.
2. Для каждой выбранной темы выполняется запрос истории с `top_msg_id`, ограниченный её `topic_id` и временным окном дайджеста.
3. Каждая тема становится отдельным логическим входом суммаризатора с названием вида `Бердянск Свежие Объявления — Проблемы ЖКХ`. Это не создаёт новый Telegram-источник и не дублирует запросы.
4. Ссылки на исходные сообщения строятся по публичному имени группы и ID сообщения.
5. Если одна тема временно недоступна или возвращает ошибку, сбор остальных источников продолжается; ошибка логируется.

## Обратная совместимость

- Существующие каналы, группы и источники без `topics` не меняются.
- В конфигурации продакшена текущая запись полного `@Berdyansk_drb` заменяется записью с двумя темами.
- AI-фильтры рекламы остаются дополнительным уровнем защиты, но сообщения из невыбранных тем отбрасываются до обращения к модели.

## Проверка

Нужны тесты на:

- загрузку `topics` из YAML;
- формирование двух логических входов из одного Telegram-источника;
- передачу `top_msg_id` в Telegram-запрос;
- сохранение прежнего поведения для источника без тем;
- продолжение сбора при ошибке одной темы.

Критерий готовности: в логах запуска источник отображается с двумя выбранными темами, а сообщения из остальных тем не передаются суммаризатору.
