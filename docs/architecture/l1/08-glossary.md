## Глоссарий

<div class="tw">

| Термин | Что означает |
| --- | --- |
| **Издание** (edition) | Городское медиа со своей географией, источниками, расписанием и каналом. Сейчас одно — Бердянск. |
| **Источник** (source) | Telegram-канал или чат, который читает система. |
| **Сообщение и его версии** (source item, revision) | Сообщение из источника. Если автор его отредактировал, сохраняется новая версия; старая остаётся для истории. |
| **Фрагмент** (fragment) | Смысловой кусок сообщения: длинный пост делится на несколько фрагментов, короткая реплика остаётся целой. |
| **Смысловой отпечаток** (эмбеддинг, embedding) | Набор чисел, описывающий смысл фрагмента. Близкие по смыслу фрагменты имеют близкие отпечатки, даже если написаны разными словами. |
| **Сюжет** (Story) | Группа фрагментов об одном событии или ситуации, например «нет воды на Колонии». Сюжет — единица знания, а не абзац выпуска. |
| **Фильтр сюжетов** (Gate) | Шаг, на котором языковая модель решает о сюжете три вещи: касается ли он города (scope), оставлять ли его (retention) и нужен ли подробный разбор (enrichment). |
| **Выжимка** (brief) | Короткое описание сюжета, которое фильтр пишет для каждого оставленного сюжета. |
| **Подробный разбор** (Rich Analysis) | Для важных сюжетов модель выписывает факты, состояния служб, цитаты и неопределённости — каждое с точной ссылкой на фрагменты. |
| **Свидетельство** (evidence) | Один факт сюжета с типом: сообщение жителя, официальное заявление, состояние службы, вопрос жителя, коммерческое предложение. |
| **Заявка на выпуск** (publication intent) | Запись «нужен такой-то выпуск к такому-то времени». Создаётся по расписанию или по команде владельца и проходит этапы: сбор → обработка → готово → подготовка → выпуск. |
| **Снимок знаний** (knowledge snapshot) | Момент, по состоянию на который берутся сюжеты для выпуска. Всё, что пришло позже, в этот выпуск не попадает. |
| **Отбор** (selection) | Решение, какие сюжеты попадают в выпуск и с каким весом. Управляет подачей, а не проверкой фактов. |
| **План подачи** (presentation plan) | Раскладка отобранных сюжетов по рубрикам дайджеста, которую получает модель-автор. |
| **Граница доказательств** (Evidence Boundary) | Детерминированная проверка текста: всё, что утверждается, должно найтись в исходных сообщениях. |
| **Редактор-корректор** (editor) | Повторный вызов модели, которая исправляет только отмеченные проверкой места, а не переписывает текст целиком. |
| **Отказ без запасного варианта** (fail-closed) | Если проверенного текста нет, выпуск не публикуется; склейка сообщений вместо текста запрещена. |
| **Рубрика** | Тематический блок дайджеста: «Коммунальная обстановка», «Транспорт и дороги», «Связь и интернет» и другие. |
| **Лонгрид** | Статья о жизни города на Telegra.ph: ежедневная, «Итоги недели» по воскресеньям и итоги периода. Крупные сюжеты раскрыты подробно, мелкие — коротко, конкретные детали сохранены. |
| **Глубина подачи** (DEVELOP / WEAVE / BRIEF) | Сколько места сюжет получает в статье: развернуть на несколько абзацев, вплести в раздел или упомянуть одной фразой. Не решает, допускать ли сюжет. |
| **Досье автора** | Подготовленный для модели-автора материал статьи: факты с id опор, детали, география и список дословных цитат, которые можно использовать. |
| **Сюжетная линия** (storyline) | Долгая история внутри темы, например «перебои со светом в нагорной части»: объединяет сюжеты многих недель. |
| **Хроника** (chronicle) | Записи о сюжетных линиях по неделям, месяцам, кварталам и годам. Служит навигацией для итогов периода, но не источником фактов. |
| **Итоги периода** (period review) | Обзор закрытого месяца, квартала, полугодия или года, построенный по хронике. |
| **Память о ситуациях** (situation memory) | Короткий список долгих ситуаций в городе, который дайджест получает как фон. |

</div>

### Названия компонентов в документе и в коде {#l1-names}

В документе компоненты названы по роли. В коде и при развёртывании у них технические имена — вот соответствие. Пути к файлам — на Уровне 3: [Репозиторий и стек](#l3-repositories).

<div class="tw">

| В документе | В коде / Docker Compose | Что это |
| --- | --- | --- |
| **Бот издания** | `telebrief-app` (`bot_commands`) | Команды владельца в Telegram |
| **Управление выпусками** | `schedules`, `orchestrator`, `readiness` | Расписание, заявки, проверка готовности |
| **Сбор** | `ingestion`, `providers` | Чтение Telegram и Facebook |
| **Обработка знаний** | `processing` | Фрагменты, эмбеддинги, сюжеты, Gate, разбор |
| **Редакция** | `publication` | Отбор, дайджест, статья, проверка |
| **Доставка** | `publication.delivery`, `sender`, `telegraph` | Посты в канал и страницы Telegra.ph |
| **База данных** | `postgres` (PostgreSQL + pgvector) | Данные и очередь задач Procrastinate |
| **Фоновые обработчики** | `telebrief-worker`, `telebrief-processing-worker`, `telebrief-authority-worker` | Процессы, которые выполняют задачи из очереди |
| **Фоновое обслуживание** | очередь `maintenance` (`jobs/maintenance`) | Хроника, память о ситуациях, очистка, восстановление задач, проверка баланса |

</div>

### Сокращения {#l1-abbreviations}

<div class="tw">

| Сокращение | Расшифровка и значение |
| --- | --- |
| **ADR** | Architecture Decision Record — запись архитектурного решения. |
| **LLM** | Large Language Model — языковая модель, которая пишет и анализирует текст. |
| **Gate** | Фильтр сюжетов (см. выше). |
| **LOCAL / DIRECT_IMPACT** | Сюжет произошёл в городе / произошёл вне города, но прямо влияет на жителей. |
| **KEEP / DROP** | Оставить сюжет / отбросить как шум или чистую рекламу. |
| **MCP** | Model Context Protocol — необязательный интерфейс, через который ИИ-агенты могут запрашивать дайджесты. |
| **UTC** | Всемирное время. Сервер работает в UTC, расписание выпусков задаётся по Киеву. |
| **ERD** | Entity-Relationship Diagram — схема таблиц базы и связей. |

</div>
