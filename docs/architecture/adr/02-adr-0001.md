## ADR-0001: Сюжеты из смысловых кластеров вместо разбора каждого сообщения (Event-First)

<p class="adr-meta"><span class="badge badge-ok">Принято</span> · Дата: 2026-08-29 · Касается: <a href="#l2-ingestion">Сценарий 1</a>, <a href="#l2-digest">Сценарий 2</a></p>

### Контекст и проблема

Издание читает десятки, а в перспективе сотни городских чатов. За сутки приходят тысячи сообщений, большинство — короткие реплики, которые понятны только в контексте разговора. Знания о городе должны накапливаться между выпусками, а каждое опубликованное утверждение — вести к конкретному сообщению.

### Движущие факторы

- Стоимость не должна расти пропорционально числу сообщений.
- Короткая реплика («Колония нету») понимается вместе с соседними сообщениями.
- Каждое утверждение в выпуске прослеживается до исходного фрагмента.
- Знания хранятся отдельно от того, как их подаст конкретный выпуск.

### Рассмотренные варианты

- **Пересказ окна целиком при выпуске** (прежний путь «по сообщениям»: `src/summarizer.py`, `src/grouper.py`). Нет накопленных знаний, нет точной привязки утверждения к сообщению, объём окна ограничен контекстом модели.
- **Извлечение утверждений из каждого сообщения моделью** (claim-first: таблицы `claims`, `claim_*`). Тысячи вызовов модели в сутки; одна и та же новость дробится на десятки похожих утверждений.
- **Event-First:** дешёвая детерминированная подготовка и векторная кластеризация, а модель работает уже с сюжетами.

### Решение

Event-First. Сообщения режутся на фрагменты по правилам, получают эмбеддинги пачками и собираются в сюжеты по смысловой и временной близости. Модель вызывается на уровне сюжетов: Gate — пачками, Rich Analysis — только для сюжетов, которым нужен разбор. Каждое свидетельство сюжета хранит точные id фрагментов.

### Последствия

- Число вызовов модели зависит от числа сюжетов, а не сообщений.
- Сюжет — единица знаний, а не пункт выпуска: несколько сюжетов могут стать одним пунктом дайджеста, и это задача слоя публикации, а не кластеризации.
- Качество зависит от эмбеддингов и порогов объединения; для коротких реплик нужны отдельные правила (присоединение по ответу или по соседнему сообщению).
- Смысл сохранённых решений версионируется; после изменения Gate или анализа старые ревизии нужно пересчитать, иначе выпуск читает прежнюю семантику.
